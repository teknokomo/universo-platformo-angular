# Universo Platformo Angular

Реализация **Universo Platformo** на **Angular** (фронтенд) и **Gin / Go** (бэкенд) с TypeScript и Go.
Supabase используется как база данных и провайдер аутентификации — доступ осуществляется **исключительно через бэкенд**.
Фронтенд никогда не обращается к Supabase напрямую.

## Технологический стек

| Уровень | Технология |
|---------|-----------|
| Фронтенд | Angular 17+ · TypeScript · Angular Material |
| Бэкенд | Go 1.21+ · Gin · gin-contrib/sessions · gin-contrib/cors |
| Провайдер аутентификации | Supabase (только через Go-бэкенд) |
| Хранение сессий | Подписанный HTTP-Only cookie (на стороне сервера, 7 дней) |
| CSRF-защита | Double-submit токен, хранящийся в сессии |
| Менеджер пакетов | PNPM workspaces |
| i18n | ngx-translate |

## Архитектура

Все функции реализованы в виде **независимых пакетов** в директории `packages/`.
Каждый пакет имеет директорию `base/` с основной реализацией и двуязычный README (EN + RU).
Пакеты фронтенда используют суффикс `-frt`; пакеты бэкенда — суффикс `-srv`.

```
packages/
├── auth-frt/base/    Angular-модуль аутентификации (сервис, guards, компоненты)
├── auth-srv/base/    Go/Gin-сервер аутентификации (прокси к Supabase)
└── start-frt/base/  Angular стартовые страницы (лендинг для гостей + мастер онбординга)
```

## Как работает интеграция с Supabase

```
Браузер (Angular)
      │  HTTP (сессионный cookie + CSRF-токен)
      ▼
Go/Gin auth-srv
      │  HTTPS (заголовок apikey)
      ▼
Supabase Auth API
```

Angular-фронтенд обращается только к эндпоинтам `/api/v1/auth/*` на Go-бэкенде.
Go-бэкенд хранит `SUPABASE_URL` и `SUPABASE_ANON_KEY` — браузер их никогда не видит.
Бэкенд проксирует вход, регистрацию, обновление токена и выход в Supabase от имени пользователя.

## Реализованные пакеты

### `packages/auth-srv/base` — Go/Gin бэкенд аутентификации

| Эндпоинт | Метод | Доступ | Описание |
|----------|-------|--------|----------|
| `/api/v1/auth/csrf` | GET | — | Выдать CSRF-токен для сессии |
| `/api/v1/auth/login` | POST | CSRF | Аутентификация по email + паролю |
| `/api/v1/auth/register` | POST | CSRF | Регистрация нового аккаунта |
| `/api/v1/auth/me` | GET | сессия | Вернуть текущего пользователя; автообновление токена |
| `/api/v1/auth/logout` | POST | CSRF | Завершить сессию и Supabase-токен |
| `/health` | GET | — | Проверка работоспособности |

Ключевые особенности реализации:
- Сессии хранятся на стороне сервера в подписанном cookie (`gin-contrib/sessions`)
- CSRF-токены генерируются через `crypto/rand`, проверяются при каждом запросе
- Токены Supabase никогда не попадают в браузер
- Cookie `Secure` и `SameSite` настраиваются через переменные окружения
- Все HTTP-запросы к Supabase используют контекст запроса для корректной отмены

### `packages/auth-frt/base` — Angular-фронтенд аутентификации

Предоставляет реактивное состояние аутентификации для всего Angular-приложения:

- **`AuthService`** — состояние на основе `BehaviorSubject` (`user$`, `isAuthenticated$`, `loading$`)
- **`authGuard`** / **`guestGuard`** — функциональные guards маршрутов (Angular 17+)
- **`LoginFormComponent`** — Material-форма входа по email/паролю с валидацией
- **`RegisterFormComponent`** — Форма регистрации с подтверждением пароля и правовыми чекбоксами
- **`AuthViewComponent`** — Карточка с вкладками для форм входа и регистрации

### `packages/start-frt/base` — Angular стартовые страницы

- **`StartPageComponent`** — Умный маршрутизатор: показывает гостевой или авторизованный вид в зависимости от состояния
- **`GuestStartPageComponent`** — Лендинг для гостей с карточками функций и CTA → `/auth`
- **`AuthenticatedStartPageComponent`** — Трёхшаговый мастер онбординга (Проекты → Кампании → Кластеры)
- **`StartFooterComponent`** — Общий подвал со ссылками на политику конфиденциальности и условия

## Начало работы

### Предварительные требования

- Node.js 18+ и PNPM 8+
- Go 1.21+
- Проект [Supabase](https://supabase.com) с включённой аутентификацией по email/паролю

### Настройка бэкенда

```bash
cd packages/auth-srv/base
cp .env.example .env
# Заполните SUPABASE_URL, SUPABASE_ANON_KEY, SESSION_SECRET
go run cmd/server/main.go
```

### Настройка фронтенда

```bash
pnpm install
# Запустите Angular-приложение, использующее @universo/auth-frt и @universo/start-frt
```

## Заметки по безопасности

- Установите `SECURE_COOKIE=true` в production (требует HTTPS)
- Используйте надёжный случайный `SESSION_SECRET` (≥ 32 символов)
- `SUPABASE_ANON_KEY` находится только на бэкенде — никогда не в бандлах фронтенда
- CSRF-токены создаются заново для каждой сессии и проверяются при каждом изменяющем состояние запросе

## Соглашения о пакетах

- **Именование**: `{feature}-frt` (Angular) или `{feature}-srv` (Go/Gin)
- **Структура**: Каждый пакет имеет директорию `base/` с реализацией
- **Документация**: Каждый пакет имеет двуязычные `README.md` + `README-RU.md`
- **Независимость**: Пакеты предоставляют чётко определённые публичные API для межпакетного использования

## Дорожная карта проекта

1. **Фаза 1 (текущая)**: Все пакеты как workspace-пакеты в этом монорепозитории
2. **Фаза 2**: Зрелые пакеты извлекаются в отдельные репозитории
3. **Фаза 3**: Остаются только инфраструктурные пакеты; функции полностью независимы
